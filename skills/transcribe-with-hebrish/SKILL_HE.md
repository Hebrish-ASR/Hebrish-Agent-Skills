# תמלול עם Hebrish

Hebrish היא אפליקציית ההכתבה של דניאל רוזהיל, פרויקט של אדם אחד (hebrish.app). אפליקציית שולחן
העבודה יכולה להגיש את המודל שטעון בה כ-**API מקומי**: תוכנה באותו מחשב שולחת קובץ שמע ומקבלת
בחזרה את הטקסט. שום דבר לא יוצא מהמחשב ואין מפתח API. הפלט הוא אנגלית שבה מילים בעברית כתובות
בתעתיק לטיני (*makolet*, *arnona*), אף פעם לא באותיות עבריות.

## כללים לסוכן

- ה-API נמצא בכתובת `http://127.0.0.1:8723`, אלא אם המשתמש שינה את הפורט בהגדרות, Local API.
  הוא עונה רק במחשב הזה.
- שלחו את הקבצים כמו שהם: האפליקציה ממירה כל פורמט ש-ffmpeg קורא. אל תדגמו מחדש ואל תפצלו אותם
  מראש; קבצים ארוכים האפליקציה מפצלת בעצמה.
- אל תשלחו כותרת `Origin` כמו של דפדפן: בקשות עם כותרת כזו נדחות (403).
- בקשה אחת בכל פעם מספיקה; האפליקציה מפענחת על המעבד ומסדרת בקשות בתור, זו אחרי זו ואחרי
  ההכתבה של המשתמש עצמו.
- בטקסט אין פסקאות. אם המשתמש רוצה פסקאות או סיכום, עשו זאת בעצמכם מהטקסט שהתקבל, ואמרו זאת.

## 1. בדיקה שה-API פועל

```bash
curl -s http://127.0.0.1:8723/health
```

- `{"status": "ok", ... "model": {...}}`: מוכן. ספרו למשתמש איזה מודל עונה (`model.name`).
- `{"status": "no_model", ...}`: Hebrish פועלת אבל עוד לא נטען מודל (עדיין בהורדה או בטעינה).
  חכו, או בקשו מהמשתמש לבחור מודל בלשונית Models.
- החיבור נדחה, או שאין תשובה: ה-API המקומי כבוי, או ש-Hebrish לא פועלת. בקשו מהמשתמש לפתוח את
  Hebrish, לעבור אל **Settings → Local API** ולסמן את *Serve transcription to apps on this
  computer*. אם הוא מעדיף שתעשו זאת אתם, הגדירו `"local_api": true` בקובץ ההגדרות
  (`~/.config/hebrish/config.json` בלינוקס, `%APPDATA%\Hebrish\config.json` בווינדוס) כש-Hebrish
  סגורה, ואז הפעילו את Hebrish שוב. אם אין בהגדרות כרטיס Local API, האפליקציה ישנה מדי: עדכנו
  אותה (באובונטו, `sudo apt update && sudo apt install hebrish`).
- כרטיס Local API אומר שהפורט תפוס: תוכנה אחרת משתמשת ב-8723. המשתמש יכול לבחור שם פורט אחר;
  השתמשו בפורט הזה בהמשך.

## 2. תמלול קובץ

טקסט פשוט:

```bash
curl -s http://127.0.0.1:8723/v1/audio/transcriptions \
  -F file=@"/path/to/note.mp3" -F response_format=text
```

JSON, עם אורך השמע וזמן העיבוד:

```bash
curl -s http://127.0.0.1:8723/v1/audio/transcriptions \
  -F file=@"/path/to/note.mp3" -F response_format=verbose_json
```

`response_format` הוא `json` (ברירת המחדל, `{"text": "..."}`), `text` או `verbose_json`
(`text`, `duration`, `processing_s`, `model`). צפו לכ-5 עד 10 שניות עיבוד לכל דקת שמע על מעבד
של מחשב נייד עדכני.

שגיאות חוזרות בצורה `{"error": {"message": "..."}}`: 400 הקובץ לא נקרא כשמע (התקינו `ffmpeg`
לפורמטים שאינם wav,‏ flac,‏ ogg ו-mp3), 503 אין מודל טעון, 413 קובץ מעל 1 GB.

## 3. תיקיית הקלטות

כתבו כל תמליל ליד ההקלטה שלו, ודלגו על מה שכבר תומלל:

```bash
for f in /path/to/folder/*.{mp3,m4a,wav,ogg,flac}; do
  [ -e "$f" ] || continue
  out="${f%.*}.txt"
  [ -e "$out" ] && continue
  curl -sf http://127.0.0.1:8723/v1/audio/transcriptions \
    -F file=@"$f" -F response_format=text > "$out" || { rm -f "$out"; echo "failed: $f"; }
done
```

שאלו לפני שאתם כותבים לתיקייה שהמשתמש לא ציין.

## 4. מתוך קוד

נקודת הקצה תואמת את API התמלול של OpenAI, כך שערכות ה-SDK של OpenAI עובדות עם כתובת בסיס אחרת;
ה-SDK דורש מפתח, וכל ערך מתאים (`export OPENAI_API_KEY=local`):

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8723/v1")
with open("note.mp3", "rb") as f:
    print(client.audio.transcriptions.create(model="hebrish", file=f).text)
```

המערכת מתעלמת מ-`model`: עונה המודל שטעון באפליקציה. כדי להחליף אותו, המשתמש בוחר מודל אחר
בלשונית Models של Hebrish.

## מגבלות

- המודלים אומנו על קולו של דובר אחד; קולות אחרים עובדים, עם יותר שגיאות.
- דיבור שכולו בעברית אינו מה ש-Hebrish נועדה לו: היא כותבת אנגלית, עם מילים בעברית בתעתיק לטיני.
- מצב התמלול (Transcription Mode) באפליקציה נותן את אותו טקסט, ועוד פסקאות ומודל הניקוי
  האופציונלי; ה-API מחזיר את הטקסט בלעדיהם, ושום דבר לא נשמר בהיסטוריה של האפליקציה.
